# UX 审查：交互习惯对照主流电子书软件

> 日期：2026-09-11　范围：书库 + 阅读器全部交互　方法：**真机实测**（Playwright 驱动真实 Chromium 走完整流程）+ 代码级核对 + 主流软件文档取证
> 结论先行：**核心阅读体验（连续滚动 / 排版调节 / 目录 / 脚注 / 高亮笔记）方向是对的**，但有三处会**直接坑到用户**，另有 6 项是主流软件人人都有、我们缺了会被觉得"功能少"的。

## 一、当前交互全景（实测，非自述）

### 书库
| 项 | 现状 |
|---|---|
| 导入 | 「导入书籍」按钮 + **整页拖拽**；单本；**不检测重复** |
| 卡片信息 | 封面、书名、作者、进度条、百分比 + 「继续阅读」/「尚未开始」、「从头读」（仅已读过的书）、「已读 X · 读了 N 次」 |
| 排序 | **仅按导入时间倒序**，无其他排序/分组/筛选 |
| 删除 | 卡片右上角 `×` → **立即删除**（书 + 进度 + 书签 + 笔记 + 统计），**无确认、无撤销、无回收站** |

### 阅读器
| 项 | 现状 |
|---|---|
| 翻页 | **仅连续滚动一种** |
| 键盘 | `←`/`PageUp` 上翻一屏、`→`/`PageDown`/`空格` 下翻一屏、`Home` 回顶、`Esc` 关面板（无面板则退出） |
| 鼠标 | 仅滚轮；**点正文任意位置无反应** |
| 触摸 | **零手势支持** |
| 顶栏 | `← 书库` / 书名 / `目录` / `排版` / `书签 N` / `搜索` / `笔记 N` / `百分比`；**常驻不隐藏** |
| 进度口径 | **只有一个百分比** |
| 目录 | 树形、当前章高亮、支持章内锚点跳转 |
| 排版 | 字号 14–28 / 行距 1.4–2.8 / 正文宽 480–900 / 5 内置字体 + 自定义上传 / 3 主题（日间·护眼·夜间）；**全局共用，跟随系统深色无** |
| 书签 | 需先开「书签」面板 → 点「添加当前书签」；**无快捷键、无工具栏一键** |
| 搜索 | 顶部面板 → 输入实时检索**本书**；**无 `Ctrl+F`** |
| 高亮笔记 | 框选 → 确认浮层 → 入库；点高亮 → 写/改/删笔记；管理面板可勾选、导出、删除、跳转；**只有一种颜色** |
| 提示 | 恢复阅读位置有 toast |

## 三、问题清单（按严重度分级）

### 🔴 P0 — 会直接坑用户（数据安全 / 基本可用性）

> **2026-09-12 更新：P0-1 / P0-2 / P0-3 已全部修复**（`9c0f05e` 删除确认与撤销、`b01d305` ↑↓ 翻屏与容器可聚焦、本次触屏手势）。
> 三条均已在**真机**复核通过（Playwright + 本机 Chrome，其中 P0-3 用 390×844 触屏视口）。下面保留原始问题描述作为决策记录。
> 剩余待办见 P1 一节。

**P0-1　删书无二次确认，且不可撤销**（✅ 已修）
- 实测：点击 `×` 时 `window.confirm` 调用 **0 次**，书架从 1 本直接变 0 本。
- 后果：一个误触，**书 + 进度 + 书签 + 全部笔记 + 统计**一次性蒸发。用户导一本 70MB 的 OCR 脏书要花时间，笔记更是心血。
- 主流做法：Apple Books 删除给三个选项（移出"正在读"/删除下载/彻底删除）；Kindle、微信读书、Koodo 均需确认。
- 建议：**最低成本**——加确认对话框；**更好**——删除后弹「已移除 · 撤销」toast（8 秒内可恢复，需把删除数据暂存一下）。同时把 `×` 从"贴着卡片的小角标"改成明确语义（如悬停才显形的"移出书架"）。

**P0-2　↑/↓ 方向键完全失效（实测 Δ 0）**（✅ 已修）
- 实测：`ArrowDown`/`ArrowUp` 的 `scrollTop` 增量为 **0**；`←`/`→`/`空格`/`PageDown` 正常（Δ 693）。
- 根因：键盘处理只接了 `ArrowLeft/ArrowRight/PageUp/PageDown/Home`，**漏了 `ArrowUp/ArrowDown`**；且 `.reader-scroll` 的 `tabIndex = -1`（不可聚焦），浏览器也没法兜底滚动。
- 后果：用户下意识按上下键翻页 → 毫无反应 → 判定"这软件坏了"。
- 主流做法：Thorium 明确「方向键 = 上一页/下一页（分页关闭时即滚动单位）」，即四个方向键都该管用。
- 建议：`ArrowUp/ArrowDown` 接入翻屏（与 `←`/`→` 同义）；顺手给容器 `tabIndex={0}`，兼顾键盘可达性与无障碍。

**P0-3　零触摸/手势支持**
- 实测：点左侧 15% / 右侧 85% / 正中，`scrollTop` 增量全为 **0**，**且不弹出任何面板**。
- 后果：**手机上几乎不可用**——不能点按翻页、不能滑动翻页、不能点中间唤菜单。桌面版尚可（滚轮 + 键盘），但网页版一旦在手机上打开就是"能看不能翻"。
- 主流做法：Apple Books（点左右页边 = 翻页，可开关）、Kindle、微信读书（仿真/左右/上下三种）、Koodo 均把触控当第一输入。
- 建议：若短期只保桌面，请在 README 明确"暂不支持触屏"；若要补，最小实现是 **左右滑动翻屏 + 点按左右区域翻屏 + 点中间唤出/隐藏顶栏**。
- **✅ 已修（2026-09-12）**：新增 `src/lib/gestures.ts`（纯函数：分区/点按/滑动判定，13 例单测）。阅读页接 `onTouchStart/onTouchEnd`：
  - 点左 / 右 22% 边缘 = 上一屏 / 下一屏；左右滑动（横距 ≥45px、纵向不主导、<700ms）同义；两者都用平滑滚动，步长与键盘一致（一屏 − 48px）。
  - 点中间（剩余 56%）= 收起 / 唤出顶栏（`.reader.is-chrome-hidden`），手机上多出一整行正文。
  - 落在 `a / button / mark / img / input` 上的点按**不翻页**（否则点脚注会顺带翻一屏）；有选区（选词加高亮）不翻页；侧栏开着时点正文只关侧栏。
  - 只认 `touch`：**鼠标点击不参与**（鼠标点正文有选词 / 放光标语义，一并当翻页会废掉高亮功能）。
  - 顺带补手机适配：`touch-action: pan-y` + `overscroll-behavior-y: contain`（关下拉刷新）；≤720px 时顶栏横向可滑、按钮加大到 36px、正文左右留白收窄。
  - 真机实测（390×844 触屏）：点右 Δ+747、点左 Δ−747、右→左划 +747、左→右划 −747、点中间顶栏收起且 Δ 0、上下划 Δ 722 未被当成翻页、hash 未跳回书库、无 JS 报错。

### 📱 手机端专项（2026-09-12 真机 iPhone Safari 实测补充，三条均已修）

> 来源：主上大人在 iPhone Safari 上实际使用后反馈（截图为证）。

**M-1　侧栏遮满屏、且能互相叠加**（✅ 已修 `已提交`）
- 实测：390px 宽屏上「目录」(280px) 与「排版」(300px) 可同时打开 = 580px，正文被压成一条缝，右侧「排版」面板被裁掉一半，字体/主题两行看不见。
- 修法：面板**互斥**（一次只开一个）；≤720px 时侧栏改为**底部浮层**（宽 100%、高 ≤78vh、圆角阴影），正文区不再被挤窄；加遮罩，点遮罩 / × 收起。
- 真机复核（Playwright 390×844 触屏）：面板 390×497、bottom=844、正文区仍 390 宽、无横向溢出、互斥成立、点遮罩可收起。

**M-2　字体在 iPhone Safari 完全无效**（✅ 已修：改为可解释 + 可自救）
- 根因不是我们的 CSS：`.chapter * { font-family: inherit !important }` 已经压住 EPUB 自带样式，字体栈确实生效了；是 **iOS Safari 的字体指纹防护会屏蔽系统字体名**，`"Kaiti SC"` 等被替换成默认字体（桌面 Chrome / Tauri 的 WKWebView 不受影响）。
- 后果：5 种内置字体在 iOS 上实际塌成 2 组（宋/楷/仿 → serif，黑/圆 → sans-serif），用户点了没反应 → 判定"设置坏了"。
- 修法：运行时探测（宽度比对法）→ 不可用的字体标灰 + 「不可用」角标 + 说明文案，把用户引导到**上传字体文件**（FontFace 注册，跨平台一致）。
- **根治仍需自带字体文件**（CJK 字体动辄数 MB，暂不引入）。

**M-3　地址栏展开时正文最后一行被遮**（✅ 已修）
- `.reader` 原用 `height: 100vh`，而 iOS 的 `100vh` 取的是**地址栏收起时**的大视口 → 底部工具栏会盖住最后一行。改用 `100dvh`（`100vh` 兜底老浏览器）。

### 🟠 P1 — 主流标配，用户会主动找

**P1-1　没有"可拖的进度条"，只有百分比**
- 现状：全屏唯一的位置反馈是顶栏一个 `0.0%`。
- 主流：微信读书可拖进度条跳转 + 左右快速切上/下一章；Kindle 有时间轴 + 缩略页；Apple/Thorium 有导航面板 + 跳页。
- 建议：顶栏（或底部）加一条细进度条，可拖可点；两端配「上一章 / 下一章」。**这是"读完一本厚书"最需要的导航能力**——尤其我们已有的样本里有 30 万字单章的书，纯滚动翻到某处很痛苦。

**P1-2　没有"本章剩余时间 / 剩余页数"**
- 现状：只有百分比。
- 主流：**Kindle 的招牌**——可在一键循环「页数 / 本章剩余时间 / 全书剩余时间 / 位置」；Apple Books 显示"本章还剩几页"。
- 建议：**与我们刚做完的阅读时长统计天然协同**——已有累计时长与会话数，再记录"阅读速度（字/分钟）"即可估算"本章还剩 X 分钟"。点击百分比即可在「百分比 / 本章剩余时间 / 全章页码」间循环（照搬 Kindle 的交互）。

**P1-3　书签入口太深，且无快捷键**
- 现状：必须「打开书签面板」→「添加当前书签」两步。
- 主流：Apple Books 工具栏一键；Kindle 点右上角；Thorium `Ctrl+B`。
- 建议：顶栏加一个独立书签图标（点一下就把当前视口位置存为书签，再点取消），并绑 `Ctrl+B`。

**P1-4　标准快捷键基本缺失**
- 实测：`Ctrl+F`（搜索）、`Ctrl+B`（书签）、`Ctrl+End`（跳末尾）**全部无反应**。
- 主流参考（Thorium，可直接照抄）：`Ctrl+F` 搜索、`Ctrl+B` 书签、`Ctrl+PageUp/PageDown` 上/下一章、`Ctrl+Home/End` 书首/书尾、`Ctrl+W` 关闭阅读、`F11` 全屏、`Ctrl+Shift+N` 目录。
- 建议：先补 **`Ctrl+F` / `Ctrl+B` / `Ctrl+Home` / `Ctrl+End` / `Ctrl+PageUp` / `Ctrl+PageDown`** 六个，成本极低、收益立竿见影。

**P1-5　"笔记"入口在零笔记时被禁用 → 功能不可发现**
- 现状：`disabled={annotations.length === 0}`，新用户根本看不到这个功能存在。
- 建议：始终可点开，空态给一句引导（"框选正文即可加高亮与笔记"）。**所有"新功能入口"都不该在用户用过之前隐藏。**

**P1-6　书库无排序 / 无筛选 / 无搜索**
- 现状：只按导入时间倒序；没有"最近阅读"排序、没有按作者/书名筛选。
- 主流：Apple Books 支持排序 + 列表/网格切换 + 藏书夹；微信读书书架**按阅读进度自动排序**；Koodo 支持全库内容搜索 + 标签。
- 建议：加一个排序下拉（**最近阅读 / 导入时间 / 书名 / 作者**）+ 书名/作者即时筛选。书一多（>20 本）这是刚需。

**P1-7　高亮只有一种颜色**
- 现状：固定浅黄。
- 主流：Apple Books 多色（黄/绿/红/蓝/紫）；Kindle 多色；微信读书多色（因"划线"是核心社交动作）。
- 建议：给 **3–5 色**（如 重点黄 / 疑问红 / 待查蓝 / 喜欢绿），并在确认浮层直接显示色块。这条对"笔记当学习工具用"的场景价值很高。

| P2-8 | **批量导入 + 重复检测** | 拖入多本一次导入；同书重复导入给提示 |
| P2-9 | **阅读统计页** | 现在我们只有卡片一行；Koodo/微信读书 有跨书汇总、周报、排行 |

### ⚪ 有意简化，不算缺陷（保持即可，但建议在 README 说明）

- **只有连续滚动**（PRD 决策：分页重排成本高）
- **单机本地、无云同步**（PRD：隐私优先，导出兜底）
- **无 PDF / TTS / 词典翻译**（PRD P2 明确砍掉）
- **桌面版与网页版书库不互通**（已说明）

## 四、建议的实施顺序

按「**先止血 → 再补齐感知 → 最后锦上添花**」排：

| 批次 | 内容 | 理由 |
|---|---|---|
| **第 1 批（止血）** | P0-1 删除确认/撤销 · P0-2 方向键 + 容器可聚焦 | 一个防数据丢失、一个防"软件像坏了"，都是几行到几十行的改动，**性价比最高** |
| **第 2 批（导航）** | P1-1 进度条 + 上/下一章 · P1-2 本章剩余时间（复用阅读统计） | 直接服务"读完一本厚书"这个 MVP 目标 |
| **第 3 批（快捷键）** | P1-3 一键书签 · P1-4 快捷键六件套 · P1-5 笔记入口解禁 | 成本极低，一次性把"专业感"补齐 |
| **第 4 批（组织）** | P1-6 书库排序/筛选 · P1-7 高亮多色 | 书变多、笔记变多之后才痛，可以稍后 |
| **第 5 批（可选）** | P0-3 触控 · P2-1 沉浸模式 · P2-2 位置历史 · 其余 P2 | 取决于是否要在手机/平板上用 |
