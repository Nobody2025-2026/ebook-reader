## 一、现状基线（已做得好，建议维持）

先说结论：项目底子很硬，下列能力已到位，**不要为了"优化"而动它们**：

- **设计系统 token 化**：`src/index.css` 用 `--bg/--surface/--fg/--muted/--line/--accent/--danger` 一套变量贯穿，三主题各重绑整块调色板，符合"设计 token 优先"原则。
- **主题对比度已过 AA**：CHANGELOG 实测三主题 5 类文字元素最低 5.37:1，达标 WCAG 2.2 AA（4.5:1）。
- **移动端布局正确**：侧栏互斥（一次只开一个）+ 底部浮层 + 遮罩；`100dvh` 解决地址栏伸缩；`touch-action: pan-y` + `overscroll-behavior-y: contain` 关下拉刷新、防横向露白；断点补了"矮屏"让横屏也走移动布局。
- **破坏性操作有防呆**：删除走"确认 + 8 秒可撤销"，默认焦点给取消、Esc 等同取消。
- **键盘可达性完整**：`↑↓←→`、空格、`PageUp/Down`、`Home/End`、`Ctrl+B/F` 等 10+ 快捷键；正文区 `tabIndex=0` 可聚焦、有可见焦点环。
- **空态 / 筛选态区分清晰**：空书架、有书但筛不出、正在导入分别给不同文案，不会误报"书架是空的"。
- **语义与 ARIA 基本到位**：`role="alertdialog"`、`aria-expanded`、`aria-pressed`、`aria-valuetext` 已用；`html lang="zh-CN"` 已设。

下面按等级列的是**尚未覆盖**的真实缺口。

## 二、分级建议（核心）

### 🔴 P0 — 紧急（影响核心功能可用性）

#### P0-1 移动端划词高亮 / 笔记无法触发（touch 路径缺失）

- **证据**：`src/components/Reader.tsx:1549` 高亮浮层只绑在 `onMouseUp`：
  ```tsx
  onMouseUp={() => openSelectionPopover()}
  ```
  而触屏手势 `handleTouchEnd`（同文件 779–827 行）在检测到有选区时**直接 return**，只保留选区、不弹浮层：
  ```tsx
  const sel = window.getSelection?.()
  if (sel && !sel.isCollapsed) return   // 选词时不翻页，但也没人去开浮层
  ```
- **后果**：手机上用户能选中文字，但"加高亮 / 写笔记"浮层永远不出现——划词高亮与笔记是本项目 headline 功能，在触屏上形同失效。
- **修复方向**：不要只在 `onMouseUp` 触发。二选一：
  1. 在 `handleTouchEnd` 的"有选区"分支里，若选区落在正文块内，调用 `openSelectionPopover()`；
  2. 更稳：在 `reader-scroll` 上加 `document` 的 `selectionchange` 监听（防抖），选区非空且 `activeAnn` 未开时弹出。
- **注意**：移动端原生选择会先弹系统"复制 / 查找"气泡，需要确认本项目的选择流程是否拦截了系统菜单（否则会出现"系统菜单 + 应用浮层"两套），并复用现有"与已有高亮重叠则提示"的逻辑。
- **预期工时**：S（0.5–1 天，含 iOS Safari / 安卓 Chrome 真机回归）

### 🟠 P1 — 高（无障碍合规与主要体验缺口）

#### P1-1 高亮颜色仅以色块传达信息（违反 WCAG 1.4.1 Use of Color）

- **证据**：四色选择 `src/index.css` 的 `.ann-color` 只有背景色；笔记管理面板里红色高亮（`export-item`）、目录均无文字标识。当前四色语义在代码里是 `yellow/red/blue/green`，但 UI 上**没有给"重点 / 疑问 / 待查 / 喜欢"之类的文字或图案标签**。
- **后果**：色觉障碍（约 8% 男性）用户无法区分这四种高亮，只靠颜色传信息属 WCAG 1.4.1 明确禁止。
- **修复方向**：色块旁补文字标签，或改用"色块 + 图标/字母"双线索；最简方案是把四色选择做成文字按钮（`黄·重点 / 红·疑问 / 蓝·待查 / 绿·喜欢`），所见即所得且零无障碍风险。
- **预期工时**：M

#### P1-2 操作结果提示未对屏幕阅读器播报（缺 `aria-live`）

- **证据**：`src/components/Reader.tsx:1997` `export-toast` 只是普通 `<div>`；`restore-hint`（书签/恢复提示）同样无 `role` / `aria-live`。对照 `shelf-toast`（`Library.tsx:378`）已正确用 `role="status"`。
- **后果**：导出 N 条、已删除、已添加书签等**结果反馈对读屏用户不可见**，等于"做了没反馈"。
- **修复方向**：给 `export-toast`、`restore-hint`、`bookmarkHint` 容器加 `role="status" aria-live="polite"`（与 `shelf-toast` 一致）。
- **预期工时**：S

#### P1-3 删除确认框无焦点陷阱（focus trap）

- **证据**：`Library.tsx:284` `confirm-dialog` 是 `role="alertdialog"` 且 `autoFocus` 给"取消"，但打开后 **Tab 仍可逃到背景元素**（未捕获焦点在对话框内循环）。
- **后果**：违反 WCAG 2.4.3（焦点顺序）/ 2.1.2（无键盘陷阱的反面——这里是没有把焦点锁住），键盘 / 读屏用户会 Tab 到背后书架，容易误触。
- **修复方向**：打开时把焦点限制在对话框内（Tab/Shift+Tab 在"取消 / 移除"间循环），关闭后焦点回到触发删除的 × 按钮。
- **预期工时**：S

#### P1-4 快捷键体系丰富但不可发现

- **证据**：已实现 `Ctrl+B`（书签）、`Ctrl+F`（搜索）、`Ctrl+Home/End`（书首/书尾）、`Ctrl+PageUp/Down`（上/下章）、`↑↓←→`、空格、Esc 共 10+ 键（见 `Reader.tsx` 键盘处理与 CHANGELOG），但**界面无任何入口说明**，且 `Ctrl+F` 等仅在面板全关时生效，用户无感知。
- **后果**：用户不知道有这些键，等于功能白做一半（与之前"剩余时间要点才出"同类可发现性坑）。
- **修复方向**：阅读页顶栏加「?」按钮打开**快捷键速查浮层**；首次进入阅读页可弹一次轻量引导（可"不再提示"）。内容直接复用现有键位表。
- **预期工时**：M

### 🟡 P2 — 中（效率与可发现性增强）

| 编号 | 建议 | 证据 / 现状 | 修复方向 | 工时 |

### 🟢 P3 — 低（润色与可选）

- **P3-1 触控目标尺寸**：移动端顶栏按钮 `min-height: 36px`、卡片删除 `24px`。已满足 WCAG 2.2 AA 24px 下限，但建议关键操作提到 **40–44px**（Apple HIG），降低误触。工时 S。
- **P3-2 封面占位美化**：`cover-fallback` 仅显示书名首字，可加渐变书脊背景提升空封面质感。工时 S。
- **P3-3 阅读统计可视化**：书库已有"已读 X 小时 · 读了 N 次"，可加小型周趋势图（需先攒时序数据）。工时 M。
- **P3-4 睡眠定时**：阅读器加"X 分钟后自动合上"，覆盖助眠场景。工时 M。
- **P3-5 对比度余量**：`--muted`（`#6b6a66`）在日间 / 护眼主题对浅底约 **4.9:1**，处于 AA 边缘。建议压深一档（如 `#5f5e5a`）留安全余量，尤其 12px 小字。工时 S。

## 五、附录：引用的 WCAG 2.2 条款

- **4.1.3 Status Messages**：操作结果用 `aria-live` 播报（对应 P1-2）
