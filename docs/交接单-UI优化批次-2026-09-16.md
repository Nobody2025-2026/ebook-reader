| 坑 | 说明 / 对策 |
|---|---|
| Vitest 并行起 worker 会挂 | 报 `Timeout waiting for worker to respond`。项目已配 `fileParallelism: false`（串行），**别去改它**。串行下 worker 启动约 20s/个，全量偏慢属正常 |

| `rm` 批量删除被拦 | 报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（按轮次累计，阈值 50）。清理时改用 `mv xxx ~/.Trash/` |

## 8. 上一轮踩过的技术坑（省得再交学费）

1. **不要并行编辑同一个文件** —— 上一轮有两次平行 `Edit` 写同一文件，后写的把先写的**整段吞掉**，表现为「改完发现改动没了、类型检查才暴露」。
   → **对同一文件的多次编辑必须串行**。
2. **TDZ 陷阱** —— 把 `openSelectionPopover` 加进手势回调的依赖数组时，它定义在回调之后会踩 `Cannot access before initialization`。已把它**整段上移到手势区之前**。
3. **jsdom 的限制** —— `Range.getBoundingClientRect` 在 jsdom 里不存在，代码已做存在性保护（浮层定位退化为 `(0,0)`）。写测试时别指望它能给出真实坐标。
4. **`jsdom` 的 `matchMedia`** —— 需在测试里自行 mock，别指望默认实现。

## 11. 续接（2026-09-16 傍晚）：§6 的真机回归做完了，三条反馈全部修掉

### 11.1 三条问题与根因

| 真机现象 | 根因 | 修法 |
|---|---|---|
| 划完词要**再点一次**才弹浮层，时灵时不灵（iPhone 最难） | 触发只押在 `touchend` 那一帧，而手机浏览器的 Selection 是**异步成型**的：先派发 `touchend`，之后才更新选区并弹系统菜单。抬手瞬间读到的还是折叠选区 → 直接 return，掉进后面的"点按"分支（收顶栏 / 翻页） | 新增 `document.selectionchange` 兜底 + 250ms 防抖 |
| 划词靠屏幕底部，浮层被截断，「加高亮 / 取消」按不到 | 定位只有一句 `top: rect.bottom + 8`：不看下方剩多少空间，也不管左右越界 | 抽出 `src/lib/popover.ts`，翻转 + 夹紧 |
| 不做选择时浮层不自动关（翻页 / 滚动都留着） | 压根没有滚动监听。浮层是 `fixed` 定位、不跟内容走，一滚就和注释的文字脱钩 | 容器 `scroll` 即收起 |

### 11.2 关键设计取舍（下一批别改回去）

1. **兜底要"手指松开才弹"**：拖选区手柄会连发 `selectionchange`，中途弹浮层会**清掉选区**，
   用户手一松发现手柄没了 —— 等于把选词打断在半路。所以用 `touchingRef` 把门，`touchend` / `touchcancel` 才放行。
2. **同一选区只弹一次**：一次划词 `selectionchange` 会连发好几遍，不去重的话每遍都 `setNoteDraft('')`，
   用户敲了一半的笔记会被清空（比"弹不出来"更气人）。用 `chapterIndex:blockIndex:start:end` 做签名。
3. **滚动关闭的例外用"有内容"而不是"有焦点"**：桌面端浮层会自动聚焦输入框；若只认焦点，
   桌面端浮层永远关不掉（这条是**单测先变红**才发现的，见 11.3）。
4. **翻转之后仍要夹紧**：`resolvePopoverPosition` 的注释承诺"整个落在视口内"，但翻转分支没验证这一点 ——
   锚点若本就在视口外，翻过去的位置同样在视口外。真浏览器复核抓到了（锚点在视口下方 1584px，浮层跟着跑出去）。
5. `prefersTouch()` 用媒体查询（`hover: none` + `pointer: coarse`），不判 UA：
   触屏笔记本接着鼠标时仍按桌面处理才是对的。
