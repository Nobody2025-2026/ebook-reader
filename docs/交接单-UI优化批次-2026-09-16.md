| 坑 | 说明 / 对策 |
|---|---|
| Vitest 并行起 worker 会挂 | 报 `Timeout waiting for worker to respond`。项目已配 `fileParallelism: false`（串行），**别去改它**。串行下 worker 启动约 20s/个，全量偏慢属正常 |

| `rm` 批量删除被拦 | 报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（按轮次累计，阈值 50）。清理时改用 `mv xxx ~/.Trash/` |

## 8. 上一轮踩过的技术坑（省得再交学费）

1. **不要并行编辑同一个文件** —— 上一轮有两次平行 `Edit` 写同一文件，后写的把先写的**整段吞掉**，表现为「改完发现改动没了、类型检查才暴露」。
   → **对同一文件的多次编辑必须串行**。
2. **TDZ 陷阱** —— 把 `openSelectionPopover` 加进手势回调的依赖数组时，它定义在回调之后会踩 `Cannot access before initialization`。已把它**整段上移到手势区之前**。
3. **jsdom 的限制** —— `Range.getBoundingClientRect` 在 jsdom 里不存在，代码已做存在性保护（浮层定位退化为 `(0,0)`）。写测试时别指望它能给出真实坐标。
4. **`jsdom` 的 `matchMedia`** —— 需在测试里自行 mock，别指望默认实现。

### 11.1 三条问题与根因

| 真机现象 | 根因 | 修法 |
|---|---|---|
| 划完词要**再点一次**才弹浮层，时灵时不灵（iPhone 最难） | 触发只押在 `touchend` 那一帧，而手机浏览器的 Selection 是**异步成型**的：先派发 `touchend`，之后才更新选区并弹系统菜单。抬手瞬间读到的还是折叠选区 → 直接 return，掉进后面的"点按"分支（收顶栏 / 翻页） | 新增 `document.selectionchange` 兜底 + 250ms 防抖 |

### 11.2 关键设计取舍（下一批别改回去）

1. **兜底要"手指松开才弹"**：拖选区手柄会连发 `selectionchange`，中途弹浮层会**清掉选区**，
   用户手一松发现手柄没了 —— 等于把选词打断在半路。所以用 `touchingRef` 把门，`touchend` / `touchcancel` 才放行。
2. **同一选区只弹一次**：一次划词 `selectionchange` 会连发好几遍，不去重的话每遍都 `setNoteDraft('')`，
   用户敲了一半的笔记会被清空（比"弹不出来"更气人）。用 `chapterIndex:blockIndex:start:end` 做签名。
3. **滚动关闭的例外用"有内容"而不是"有焦点"**：桌面端浮层会自动聚焦输入框；若只认焦点，
   桌面端浮层永远关不掉（这条是**单测先变红**才发现的，见 11.3）。
4. **翻转之后仍要夹紧**：`resolvePopoverPosition` 的注释承诺"整个落在视口内"，但翻转分支没验证这一点 ——
   锚点若本就在视口外，翻过去的位置同样在视口外。真浏览器复核抓到了（锚点在视口下方 1584px，浮层跟着跑出去）。
5. `prefersTouch()` 用媒体查询（`hover: none` + `pointer: coarse`），不判 UA：
   触屏笔记本接着鼠标时仍按桌面处理才是对的。

| 调用点 | 原失败表现 |
| --- | --- |
| `Reader.tsx` 加高亮 | 抛错 → 未捕获 rejection → 后面 `setToast('已添加高亮')` 执行不到 → **点了完全没反应** |
| 加书签 / 删书签 / 存笔记 / 改颜色 / 删高亮 | 同上 |
| 存进度 / 记时长 / 记会话 | 全是 `void xxx()`，失败彻底无声 |
| 删书 / 从头读（`App.tsx`） | 无 try/catch → 未捕获 |
| 导入（`App.tsx:131`） | ✅ 已有 catch |

### 14.2 设计决策（主上大人拍板）

1. **严格一致**：写失败就当没发生过 —— 内存状态不更新、不说"已添加"。
   理由：界面上有、库里没有的分叉，会在下次打开书时凭空消失，比加不上更让人疑神疑鬼。
2. **只管写失败**：读失败（书库空白）是另一类问题，提示方式不同，留给下一轮。
3. **不逐个糊 try/catch**：所有 `set`/`del` 走同一个 `writeGuard`，新增函数自动覆盖。
4. **后台静默写节流**：进度/时长每 30 秒写一次，次次提示是骚扰，一次不说是隐患 →
   **同一本书只提示一次**。

### 14.3 改动

- `storage.ts`：新增 `StorageWriteError`（中文原因：配额满 / 隐私模式 / 原样透传）、
  `writeGuard`、`writeErrorText`；13 个写操作全部改走守卫，**函数签名不变**。
  `deleteBook` 整体包一层（删一半失败比全失败更难解释，但至少抛出去说明白）。
- `Reader.tsx`：6 处主动写接 try/catch + toast；3 处 `void` 后台写加 `.catch` + 节流提示。
  编辑已有笔记失败时**保留浮层**（别把用户刚敲的笔记弄丢），新建高亮失败则关浮层。
- `App.tsx`：删书 / 从头读 / 导入接上回音；导入失败文案改走 `writeErrorText`。

### 14.4 验证

| --- | --- |
| `tsc --noEmit` | 0 error |
| `vitest run` | **30 文件 / 422 用例**全过（新增 13 条） |
| 回归测试有效性 | 把 `toggleCurrentBookmark` 的 catch 换成 `void err` → 2 条立刻变红 ✓ |
| 覆盖点 | 13 个写操作无一例外抛 `StorageWriteError`；失败后库里确实没变；读不受影响 |

### 14.5 踩坑（省下一位的学费）

1. **DOMException 不是 `Error` 的实例** —— `err instanceof Error` 取 `name`/`message`
   全落空。原先 quota 分支能过是巧合：`String(err)` 恰好含 "Quota"。
   新增 `errorField()` 按属性读，别再靠串匹配蒙。
2. **验证"测试有效性"时撤错了地方**：Ctrl+B 走 `toggleCurrentBookmark`，
   我撤的是 `addCurrentBookmark`，结果测试照样绿 —— 差点把假绿当真。
   **先确认被测路径到底进哪个函数**，再撤修复。
3. 快捷键绑定在 `window`（不是 document），`fireEvent.keyDown(window, ...)` 才触发。

## §16 尾巴清算：真实"写满"端到端 + 顺带抓出的漏网守卫（2026-09-19）

### 16.1 CDP 那条路死了（先记结论，省下一位的学费）

原计划用 CDP `Storage.overrideQuotaForOrigin` 把配额压到 1 字节，让**浏览器自己**抛
QuotaExceededError。实测（本机 Playwright Chromium）**根本不生效**：

- page 级 CDP session：调用返回成功，但 `Storage.getUsageAndQuota` 查回来
  `overrideActive: false`、quota 纹丝不动 —— **空转**；
- browser 级 CDP session：直接 `Internal error`。

诊断脚本在 /tmp/quota-probe*.py。**别再往这条路上花时间。**

### 16.2 替代手段：注入到原生 IndexedDB API 层

`ctx.add_init_script` 覆盖 `IDBObjectStore.prototype.put/add/delete`，开关
`window.__quotaFull` 打开时同步抛**真的 `DOMException('QuotaExceededError')`**。
比 jsdom 的模块级 mock 靠下一层（真 API 表面、真 DOMException 类型、真渲染），
残留的不真实只有"错误是我们触发的，不是浏览器自发判定的"——要消除得把
user-data-dir 挂到几十 MB 的磁盘映像上，另一个量级的工程，暂不做。

### 16.3 顺带抓到的真 bug：settings.ts / customFont.ts 绕过守卫

开关一打开，页面立刻冒出**未捕获的** `The quota has been exceeded.` —— 顺着查：

- `settings.ts`（排版设置落盘）与 `customFont.ts`(自定义字体二进制) **直接 import
  idb-keyval**，完全绕过 storage.ts 的 writeGuard —— 写失败没人接，未捕获 rejection；
- `Reader.tsx` 里 `void saveSettings(next)` 两处、`handleRemoveFont` 一处都没 catch。

修法：守卫抽到 **`src/lib/idb-guard.ts`**（单一来源），storage / settings / customFont
三个模块共用；storage.ts re-export 保持外部 import 路径不变。Reader 侧：
saveSettings 两处接 `warnSilentWrite`（**节流从"全局一次"改成"按 label 各一次"**，
否则进度先弹就把排版闭嘴了）、removeFont 加 catch、字体上传文案改 `writeErrorText`。
